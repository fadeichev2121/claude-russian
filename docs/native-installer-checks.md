# Проверка установщиков Windows и Linux

Проверки выполняются на настоящих Windows и Linux в GitHub Actions, на x64 и ARM64. Они используют официальные файлы Claude во временной папке. Claude и официальный установщик Claude не запускаются; вход в аккаунт не выполняется.

## Результат пакета 1.2.1

**5 октября 2026 года: 20 из 20 профилей прошли.** [Прогон GitHub Actions](https://github.com/fadeichev2121/claude-russian/actions/runs/37261832045), [постоянный JSON-отчёт](verification/windows-linux-1.2.1.json). Проверен код коммита `8d1921fd38d4335499a477fbe18fe087c0a3fe4c`: по 11 сценариев Windows и 9 сценариев Linux на каждый профиль.

Системы проверки: `windows-2025` (x64), `windows-11-arm` (ARM64), `ubuntu-24.04` (x64), `ubuntu-24.04-arm` (ARM64); Python 3.13.15. Другие версии Windows, дистрибутивы Linux и версии Python отдельно не запускались.

Исправлено создание промежуточных резервных папок Windows при повышенных правах и настройка прав загрузки в PowerShell 7. Добавлен явный параметр согласия для автоматизированной Windows-установки. Проверки подтверждают также сохранение отказа без согласия.

## Сборки и происхождение файлов

Пять доступных выпусков на каждую платформу, по состоянию на 4 октября 2026 года:

| Платформа | Версии | Архитектуры |
| --- | --- | --- |
| Windows | 2.19675.0, 2.16120.0, 2.9939.4, 2.9939.2, 2.7032.0 | x64, ARM64 |
| Linux | 2.9939.4, 2.7032.0, 2.2553.13, 2.2553.1, 2.2553.0 | amd64, ARM64 |

Каталог `tests/fixtures.json` содержит URL, размер и опубликованный хеш каждого исходного пакета. Windows: официальный Squirrel NUPKG и SHA-1 канала обновлений; Linux: официальный DEB и SHA-256 индекса APT. После загрузки также проверяются SHA-256 каждого изменяемого файла по профилю совместимости. Архивы и бинарные файлы не публикуются в репозитории или отчётах CI.

## Проверяемые сценарии

- Определение версии и установка перевода в исходные файлы.
- Повторная установка без создания нового патча или потери резервной копии.
- Обновление словаря через штатный откат и повторную установку; сохранение прежних исходных резервных копий.
- Отказ при неизвестном изменении файлов приложения и повреждённой резервной копии, без их перезаписи.
- Точный откат всех заменённых файлов и повторный откат.
- Отдельный запуск установщика патча и загрузка исходников из GitHub. В тесте файл установщика копируется из checkout в отдельную папку.
- Windows: согласие на изменение подписи EXE, нативный каталог, ресурс контроля ASAR и PowerShell 5.1/7.
- Linux: установка и откат ресурсов владельца root через sudo с сохранением владельца и прав файлов.

Текущий portable-патч не обновляет словарь поверх установленного перевода. Для такого обновления сначала выполни откат с прежней папкой состояния, затем установку новым пакетом.

Автоматизированные Windows-проверки передают `-ApproveExeSignature` явно. Отдельный сценарий проверяет отказ без этого параметра при перенаправленном вводе. Обычный пользовательский запуск меню сохраняет вопрос о согласии.

## Повторный запуск

Открой [Actions](https://github.com/fadeichev2121/claude-russian/actions/workflows/portable-integration.yml), выбери **Run workflow**. `smoke=true` проверяет текущую сборку на четырёх системах; `smoke=false` — все 20 профилей. Отчёты JSON сохраняются в артефактах на семь дней. Для локального запуска тестов нужен Python 3.11+ на соответствующей ОС; самому установщику достаточно Python 3.9+:

```text
python tests/portable_integration.py --profile windows-x64-2.19675.0
python3 tests/portable_integration.py --profile linux-amd64-2.9939.4
```

Linux-сценарий требует sudo для временных ресурсов владельца root. Тест изменяет словарь в своём checkout на время проверки и возвращает исходные байты; используй отдельный checkout.

## Ограничения

Эти проверки подтверждают работу установщика и отката на выбранных файлах. Отдельно остаются запуск изменённого Claude, вход, Cowork, Claude Code, системные интеграции, реакция защитных средств Windows и полнота перевода всех экранов. Новые и неизвестные сборки не становятся совместимыми автоматически.
