# Автовосстановление перевода после обновления

Пользователь одобрил обнаружение обновления, ожидание выхода из приложения, проверку совместимости, отдельный откат для каждой сборки и повторное применение для Claude и Antigravity.

## Решение
В каждом репозитории отдельная папка updater с одинаковым общим кодом manager.py, package.py, service.py и собственным adapter.py. Служба запускается только после явного включения пунктом 4 / auto-enable; выключение пунктом 5 / auto-disable. macOS LaunchAgent, Windows задача текущего пользователя, Linux systemd --user timer. Интервал 120 секунд. Нет root-службы, sudo без пароля, убийства приложений или отключения официальных обновлений.

Служебная папка вне приложения: <user-support>/<repository>/auto. В ней приватные runner, packages, states, config.json, result.json. Постоянный runner получает только опубликованные исходники этого репозитория по HTTPS, привязанные к commit SHA из GitHub; без токенов. Проверка сети не чаще раза в сутки, ошибки сети не мешают локальным поддерживаемым сборкам. Неизвестные сборки остаются нетронутыми. Новые профили должен опубликовать сопровождающий; универсальной поддержки будущих выпусков нет.

Проверка читает текущую папку (на Windows Claude выбирает новейшую app-* рядом с указанной), распознаёт ранее установленный патч по валидированной записи состояния, затем поддерживаемый оригинал по всем проверкам существующего ядра. Два одинаковых наблюдения исходной сборки с разницей не менее 60 секунд перед установкой; непосредственно перед мутацией повторный probe и штатные process/source guards. Состояние выбирается по fingerprint содержимого + пути установки, никогда по одному номеру версии. Каждое повторное применение получает отдельную папку `<fingerprint>-<uuid>`, даже если производитель вернул ту же сборку. Старые резервные копии не заменяются. Незавершённые операции блокируют повторные попытки, требуется ручной откат.

При отсутствии прав статус требует ручного применения из установщика; фоновый процесс не повышает права. Для локальной переподписи macOS и изменения EXE Claude согласие сохраняется только при явном включении. Откат отключает автовосстановление и использует актуальную совпадающую запись, а не старую резервную копию поверх новой версии. Отключение сохраняет перевод и резервные копии.

## API адаптера
- discover(app_hint): безопасный Path текущей установки; импорт существующего ядра только в контексте нужной ОС.
- probe(app, state_dirs): dict с app(str), fingerprint(64hex), version(str), kind(source/patched/unknown/busy/recovery), writable(bool), state_dir(str|None), message(str). Проверка patch state только через существующие validators; запись принадлежит app, phase installed, все patched hashes совпадают. Несовместимый оригинал kind unknown. Чужая/повреждённая запись fail closed.
- command(action, app, state_dir, approved): argv к существующему Python ядру, без оболочки; signature opt-in только approved install.
- default_state(): Path старой штатной папки состояния.

Общий manager CLI: enable (--approve-signature), disable, status, check, restore. --control-dir для явного служебного каталога; --app и --state-dir при enable (последний как дополнительная существующая запись). Параметры --app и --state-dir при check проверяются на совпадение с включённой установкой. Restore для явно выбранного другого приложения не меняет чужую включённую конфигурацию; для другого состояния текущего приложения сначала выключает её и передаёт управление штатному откату. Для restore exit 3 означает нет актуальной auto-записи, штатный установщик может предложить свой обычный откат. Enable копирует весь требуемый исходный пакет в приватную папку, создает runner, config и регистрирует пользовательское расписание. Установщики исполняют manager через свой найденный Python, не через sudo. Restore блокирует новые фоновые операции до отката.

## Проверки
Детерминированные проверки временных директорий и искусственного обновления: стабильность, exit/running, новая сборка/новая папка, сохранение предыдущего backup, неизвестный профиль, сеть offline, невозможность доступа, незавершённый patch, блокировка и rollback без повторного применения. Проверить безопасное извлечение пакетов/ссылки и генерацию расписаний. Не устанавливать реальные службы и не запускать приложения при разработке. Публикация и включение на машине пользователя отдельные действия.
